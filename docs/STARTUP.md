# 启动速度与版本约定

当前版本按用户要求重置为 **0.1.0**，现有功能继续保留。只有用户明确要求才修改版本号，功能修复、优化、构建和发布不会自动递增，见 [协作约定](../AGENTS.md)。

## 已实现的优化

- SQLite 资料读取／恢复与主窗口页面加载并行。首次资料 IPC、窗口显示与全屏偏好、关闭操作和启动链接等待同一核心就绪 Promise，避免读取空默认资料。
- 设置、完整歌词、队列、在线内容、详情、桌面歌词、替代音源、下载和评论共 9 个面板按需加载，首次解析后缓存。首屏播放器和歌曲列表直接加载。
- 音频格式解析库在真正导入音乐或读取内嵌歌词时加载；MP3 标签库在实际写入下载文件时加载。
- 同种强调色／明暗主题的官方 HCT 色彩结果使用最多 24 项缓存；返回独立结果，避免修改缓存内容。
- 已是本程序的链接协议注册不重复写入。媒体播放协议仍在创建窗口前注册，保证本地播放与 Range 请求有效。
- 启动期间退出等待在途初始化并清理资源，尚未收到真实播放状态时不把默认 0 秒覆盖到保存进度。

## Windows 实测

对照程序取自之前的 0.5.0 便携包，优化程序来自当前 0.1.0 打包 ASAR；同机连续测试，各使用一个独立资料目录。计时从启动真实 Electron 进程开始，到原生窗口已显示、音乐库已恢复、首页可见、搜索输入和关闭按钮可用，再等待两次动画帧。首次使用该独立资料目录单列记录，以下中位数来自后续 5 次重复启动。

| 指标 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 重复启动中位数 | 1040 ms | 619 ms |
| 首屏 JavaScript | 935943 字节 | 645093 字节 |
| 首屏 CSS | 112303 字节 | 79411 字节 |

本次重复启动中位数约缩短 **40%**，首屏 JavaScript 约减少 **31%**。这是本机测试，不能保证其他设备相同。新解包程序首轮观察到 8203 ms，大部分等待发生在调试连接建立之前；此测量不能确定系统层等待来源，也不是重启操作系统后的严格冷启动实验。原始首轮和每次重复启动结果均完整保留，未混入中位数。

源码交付附带 [旧版测量](../artifacts/startup-before-report.json)、[当前测量](../artifacts/startup-after-report.json) 和 [启动生命周期](../artifacts/startup-lifecycle-report.json)。首次打开延迟面板会读取对应本地构建块；不会为加载面板联网下载代码。

## 回归与缓存

31 个测试文件共 **287 项通过**。真实本地 WAV 导入／Range／播放、MP3 断点下载及 ID3、FLAC 标签及离线播放检查通过；深链接冷启动／隐藏搜索／立即退出保存、外观 14 项、设置 6 项回归通过。打包客户端的启动生命周期 5 项、基本播放及 40 组件编辑器 4 项、桌面歌词 15 项、关闭选择 9 项、Material 11 项、Windows 原生媒体会话 8 项验收通过。关闭对话框的选择使用测试桩，实际窗口关闭、隐藏、播放、SQLite 保存及进程退出是真实执行。

清理范围限定于本项目旧 `out`、`release/win-unpacked`、构建调试中间文件与 `node_modules/.vite`；随后干净重建。对照程序提取目录在测量完毕后清理。音乐文件、用户 SQLite 资料、设置及运行时缓存不在清理范围内。

## 复测

```sh
pnpm build
pnpm exec electron-builder --win --x64 --dir
node scripts/startup-performance.cjs --packaged --label=startup-after
node scripts/startup-lifecycle.cjs
# 对照程序独立放置，可指定其 EXE 路径：
node scripts/startup-performance.cjs --packaged --label=startup-before --executable=/path/to/琛瑾音乐.exe
```
